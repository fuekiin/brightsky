# Radar 3D backend, phases 2–3 (clouds, cells, operations) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the two remaining products of the brief on the `/radar3d` manifest — ICON-D2 cloud volumes with a model-wind flow field, and KONRAD3D convective cells — on the rain frames' 5-minute timeline, and make the worker cheap enough for the production box (listing traffic, peak memory).

**Architecture:** Same package, same worker container. `icon.py` reads the ICON-D2 regular-lat-lon GRIB2 files (eccodes) for the model levels that reach 12 km, samples them bilinearly onto the 2 km cloud grid (the rain grid halved), interpolates in height onto the 24 slabs, and derives one 2-D flow per column; `clouds.py` keeps the loaded runs and synthesises a cloud frame for any 5-minute stamp by semi-Lagrangian blending of the bracketing hourly steps (port of the app repo's `grid_clouds2.py`). `cells.py` ports `cells_fixture.py`. The worker gains an ICON run poller (one download per run, ~270 MB, ~45–60 min after run time), a KONRAD poller, and a predicted-filename sweep fetcher with a sparse listing fallback. Cloud frames are written whenever a rain cycle is gridded (so the stamps coincide) and, when a run arrives, for indexed rain stamps that have none yet.

**Tech Stack:** as phase 1 plus `eccodes` (pip, bundles the C library via `eccodeslib`).

**Spec:** the brief (`../WeatherGermany/docs/superpowers/specs/2026-09-17-radar-3d-backend-brief.md`), reference gridders `../WeatherGermany/tools/radar3d/grid_clouds.py`, the app session's `grid_clouds2.py` (two channels + flow), `cells_fixture.py`, and the app's decoder `WeatherCore/.../Radar/StormCell.swift`.

## Global Constraints

- Clouds: **2 km × 500 m** (`GERMANY_2KM` = 349 × 456, the rain grid halved), two interleaved channels: R = condensed water qc+qi+qs+qg in g/m³ (`v × 0.01`), G = cloud cover % (`v × 0.4`); quantised as the reference: water 0.05 g/m³ steps below 0.5, 0.1 above, nothing below 0.02; cover 25 % steps, nothing below 30 %. Air density `1.225·exp(−h/8500)`. Model full-level height = mean of the `hhl` half levels. Flow = water-weighted mean of u/v over the column, else the 3–8 km mean, in cells per 5 min. Hourly steps blended semi-Lagrangian to each 5-min stamp.
- Cloud frames exist only on rain timestamps (`clouds: null` otherwise); the flow travels in the frame's extra block; `flows_clouds: true` once any frame carries one.
- Cells: field names exactly as `cells_fixture.py` emits them (`id, lat, lon, heightM, echoTopM, echoBottomM, areaKm2, maxDbz, severity, gustKmh, gustFlag, heavyRainMm, hail, largeHail, hailTopM, hailBottomM, hailAreaKm2, lightningRate, lightningDensity, rateHistory, lightningJumps, mesoIndex, mesoBaseM, mesoTopM, cloudTopM, speedKmh, firstSeen, track`), `-1000000000` → `null`, ids may carry a `#`.
- Rain crops are now always aligned to 2 cells so a crop's bounds are identical on the 1 km and 2 km grids.
- Worker peak RSS well under 1 GB; sweep discovery must not cost 17 MB/min.
- Additive files; ruff clean; tests for every module; worklog + architecture + deployment docs updated.

### Task 1: ICON-D2 reading and vertical interpolation (`icon.py`)

Algorithms (port of `grid_clouds2.py`, vectorised):

```python
def to_slabs(field, heights, slab_h):
    """field/heights [K,H,W] ordered bottom→top (ascending heights, NaN =
    missing); linear in height at each slab centre, 0 outside → [L,H,W]."""
    K = field.shape[0]
    out = np.zeros((len(slab_h),) + field.shape[1:], np.float32)
    valid = ~np.isnan(heights) & ~np.isnan(field)
    h = np.where(valid, heights, np.nan)
    for s, hs in enumerate(slab_h):
        above = (h >= hs)                       # first valid level at/above hs
        idx1 = np.argmax(above, axis=0)         # 0 when none above
        any_above = above.any(axis=0)
        below = (h < hs)
        idx0 = K - 1 - np.argmax(below[::-1], axis=0)
        any_below = below.any(axis=0)
        ok = any_above & any_below
        h0 = np.take_along_axis(h, idx0[None], 0)[0]; h1 = ...
        v0 = ...; v1 = ...
        t = (hs - h0) / (h1 - h0)
        out[s] = np.where(ok, v0 * (1 - t) + v1 * t, 0.0)
    return out
```
NaN-masked levels must be skipped exactly as `np.interp` over the `ok` subset does; the unit test compares against a per-column `np.interp` on random data with NaN holes.

### Task 2: Cloud frames (`clouds.py`)

- `CloudModel.frame_at(ts)`: bracketing steps `lo ≤ ts ≤ hi` (a single step when equal); `w`; interpolated flow `fu, fv` (m/s) → `cx, cy` cells/s (`cell_m_x` at the grid's mid-latitude, `+y` south); `lwc = warp(lwc0, cx·s0, cy·s0)·(1−w) + warp(lwc1, −cx·s1, −cy·s1)·w`, same for `cov`; quantise → `rg[L,H,W,2]`; flow `= (cx, cy) · 300` cells per 5 min `[H,W,2]`.
- `warp(vol, dx, dy)`: pull with bilinear taps, per level, clipped sources.
- `flow_block(flow, crop)`: crop the `[H,W,2]` field, resample to `(ceil(w/4), ceil(h/4))` by bilinear sampling at the coarse cell centres, pack `<HH` + float16 pairs.

### Task 5: Worker (`ingest.py`)

1. **Predicted sweep names.** After each full listing of a site, remember per `(site, tilt)` the WMO id and the seconds-into-cycle offset of the newest file. For every cycle in the window without that `(site, tilt)`, try `GET` of the predicted name (offset −1, 0, +1 s); a 404 is silent. A full listing is taken when the site has no schedule yet, when a predicted file is more than 90 s overdue, or every `RADAR3D_LISTING_INTERVAL` (15 min, sites staggered). Cost: ~1 MB/min of listings instead of 17.
2. **Streamed gridding.** `process_cycle` no longer materialises all sites; `grid_rain` consumes the generator and a counter records the sites (peak RSS −~170 MB).
3. **ICON runs.** Every poll: candidate run = latest `run_hour ∈ {0,3,…,21}` with `run + 45 min ≤ now`; if not loaded, try to download steps 1..`RADAR3D_ICON_STEPS` (levels from `choose_levels`, u/v every third level between 1 and 10 km) into `raw/icon/<run>/`; a 404 means "not yet", retry next poll; when complete, `load_step` each step (bz2+eccodes in a thread pool), `CloudModel.add_run`, delete the raw dir, drop runs older than 6 h. `hhl` is fetched once into `<data dir>/icon-hhl/` and cached across restarts.
4. **Cloud frames.** In `process_cycle` after the rain frame: `if model.covers(cycle): write clouds + clouds_flow + index`. After `add_run`: for every indexed rain stamp within the model's coverage lacking a clouds row, write it.
5. **Cells.** Every poll: list `konrad3d/` (78 KB), download `KONRAD3D_<stamp>.xml` for stamps in the window not yet stored, parse, `write_json('cells', ts, cells)`, index product `cells`.
6. **Retention** for all products.
